FlexClock website installation and supervised verification
========================================================
Scope: Flask configuration website only. Do not run the installer against a live
race sign without reviewing its package, nginx and service changes. It was NOT run
as part of this redesign. No live network changes or service restarts were made.

Repository ownership
--------------------
LEDSign owns setup_ledsign.sh and scripts/web_network.py. web/ is an independent
LEDSign_Site Git repository, not tracked content of LEDSign. Ship BOTH changesets.
The installer clones/fast-forwards LEDSign_Site; publish the reviewed web changes
there before using it on a fresh image. Do not reset either repository. Existing
settings.json and uploaded logos remain untouched. Commit and record the exact
reviewed revisions of both repositories for a release; mutable main is not a
reproducible version pin. No release was published by this task.

Fresh image
-----------
Use Raspberry Pi OS with dhcpcd + wpa_supplicant for this backend. Bookworm images
using NetworkManager require a separately reviewed manager migration or a future
NM backend. The installer deliberately does not switch or stop network managers.
Install/configure dhcpcd on a fresh image only if that stack is intended. Establish
Ethernet and correct Wi-Fi regulatory country using OS provisioning first.
The website never restricts frequency. WPA/WPA2 Personal and open networks are
supported; WPA3-only/enterprise require OS setup. Python requirements remain in
web/requirements.txt. The setup script installs them and a root-owned helper.
Run the installer only after both reviewed repository revisions are available.
It preserves an existing controller unit and does not start the controller.
The legacy sign-ui/run-ui.sh mismatch needs a separate controller owner decision.

-----------------------------------------
First back up config/ and both checkouts securely. Keep backups of credentials
outside version control. Install from these reviewed local files:

Replace the old broad sudoers rule (after review), using sudo visudo -f

admin ALL=(root) NOPASSWD: /usr/local/libexec/flexclock/web_network.py scan, /usr/local/libexec/flexclock/web_network.py wifi, /usr/local/libexec/flexclock/web_network.py ethernet, /usr/local/libexec/flexclock/web_hostname.py ""

sudo visudo -cf /etc/sudoers.d/sign-controller-web

That last command deploys the website and requires a planned service restart;
it has not been executed. Do not restart sign-ui or any network service.
The website creates config/.web-secret (0600) on first import. Preserve it across
worker/service restarts; exclude it from version control. SC_SECRET may override
it. Use TLS at nginx on untrusted networks; set SESSION_COOKIE_SECURE when TLS
is enabled. Sessions expire after eight hours; password changes invalidate all
sessions. The existing username/hash is retained. New passwords need at least 5 characters; there are no character-class requirements.

Read-only commissioning checks
-----------------------------
systemctl is-active NetworkManager dhcpcd wpa_supplicant
systemctl show sign-web sign-ui -p ActiveState -p ExecStart
ip -j address
ip route show
wpa_cli -i wlan0 ping
wpa_cli -i wlan0 status
ss -lntu

On the inspected device: dhcpcd and wpa_supplicant active, NetworkManager inactive;
eth0 had a DHCP address, wlan0 had no address, and wpa_cli ping could not find the
wlan0 control socket. Do not enable writes until the socket is fixed through
supervised OS configuration. A generic active wpa_supplicant service is NOT proof
it manages wlan0. Confirm its unit invocation, config location, ctrl_interface,
update_config=1 and write permissions. Do not overwrite saved network blocks or
start competing instances. Any necessary service operation needs prior approval.

Wi-Fi test approval and exact command plan
-----------------------------------------
The network helper refuses writes unless root has explicitly commissioned it:
  sudo touch /etc/flexclock-network-enabled
Do not execute this now. Approval is needed first, along with resolving the
missing socket. Scan is separate: sudo -n /usr/local/libexec/flexclock/web_network.py scan
executes iw dev wlan0 scan. The scan was NOT run by this task.

The website calls the root-owned helper with JSON via stdin. For connect:
  wpa_cli -i wlan0 ping
  wpa_cli -i wlan0 add_network                  # returns ID
  wpa_cli -i wlan0 set_network ID ssid HEX_SSID
  wpa_cli -i wlan0 set_network ID scan_ssid 1
  wpa_cli -i wlan0 set_network ID key_mgmt WPA-PSK  # NONE for open
  wpa_cli -i wlan0 set_network ID psk DERIVED_KEY   # omitted for open
  wpa_cli -i wlan0 select_network ID
  wpa_cli -i wlan0 status                      # poll up to 20 seconds
  wpa_cli -i wlan0 save_config                 # after matching COMPLETED + ID
  ip -4 -o addr show dev wlan0
Failure cleanup: wpa_cli -i wlan0 remove_network ID; wpa_cli -i wlan0 reconfigure.
Disconnect: wpa_cli -i wlan0 disable_network all; save_config; disconnect.
All commands target wlan0. No eth0 flush, manager switch or global restart.
The passphrase is delivered over stdin and converted to a derived key, never
included verbatim in a process argument or log. Derived keys are still secrets.
Saved profiles accumulate when switching; profile deletion/dedup is future work.

With Ethernet continuously monitored from another terminal, approve and test a
known WPA2 network, an incorrect password, an open network and a hidden SSID.
Compare eth0 addresses/routes before and after. Verify association using wpa_cli
and verify assigned IPv4 separately with ip. Verify reachability over each
interface from another machine. Saving a profile alone does not establish reboot
persistence. Schedule an explicitly approved reboot separately and repeat checks.
Do not reboot as part of automated tests. Lock again after testing:
  sudo rm /etc/flexclock-network-enabled

Ethernet verification (mocked first; NO live test performed)
----------------------------------------------------------
Review DHCP/static values in the Network form and its confirmation. The helper
validates IPv4, subnet, gateway and DNS, backs up /etc/dhcpcd.conf to
/etc/dhcpcd.conf.flexclock-backup, replaces only the LEDSign eth0 tagged block,
and executes: dhcpcd -n eth0
It rejects unmanaged interface eth0/profile declarations. No manager restart.
A rebind request is not proof of DHCP success. Do not exercise on the live device
during automated tests. For a future approved static test reconnect at the new
IP. For DHCP obtain the address from the router. Keep console access for manual
recovery. A failed rebind may leave the saved config changed; inspect the backup
before an approved restore/rebind. Each apply replaces the prior backup.

Full-Color LED Race Clock redesign — October 25, 2026
---------------------------------------------------
Current product name: FlexClock — Full-Color LED Race Clock. Shared sidebar and
mobile navigation, colored status cards, separate connection summaries, grouped
Settings, saved-logo previews and RGB clock presentation replace the original UI.
Static asset URLs include a content hash to bypass the previous cached CSS/JS.
No new dependencies or frontend build step are needed.

Password policy: minimum 5, maximum 128 characters. No uppercase, lowercase,
number or symbol requirement; no strength meter. The current password is required.
Storage remains hashed; password changes invalidate existing sessions.

Hostname management uses the installed /usr/bin/hostnamectl mechanism. The separate
root-owned /usr/local/libexec/flexclock/web_hostname.py helper takes JSON on stdin,
accepts only 1–63 lowercase ASCII letters/numbers/hyphens with alphanumeric ends,
and rejects requests without explicit confirmation. sudoers permits no command
arguments for this helper, denoted by the empty double quotes in the rule above.
Flask requires a valid authenticated session, CSRF token and confirmation checkbox.
The helper revalidates input, runs hostnamectl without a shell, then checks the
saved static name. It does not restart network services or the LED controller.
Its commands after a confirmed request are exactly:
  /usr/bin/hostnamectl set-hostname VALIDATED_NAME
  /usr/bin/hostnamectl --static
A failure to verify is reported as such; it is not described as success.
Hostname changes may affect name-based discovery; do not promise immediate mDNS
or DHCP propagation. No hostname change was executed during development/tests.
The hostname setting is separate from the network-write guard. Do not enable
/etc/flexclock-network-enabled when deploying this helper.

Deployment for this revision: install only the additional hostname helper and
validate/install the revised narrow sudoers file, then restart only sign-web.
Preserve the current hostname, password, device config, assets and other services.
The complete installer is not needed for an existing Pi.

Verification: run the existing web unittest command (now 28 tests). The new
hostname operations are mocked. Browser checks, an approved real hostname
change/name discovery check and Wi-Fi commissioning remain separate live tests.
Inspect sign-ui restart counts in System Information; a restarting service is
reported as needing attention, not as a healthy starting controller.

Device-name input correction
----------------------------
Mixed-case device names are accepted in the form and normalized before validation
and saving: FlexClock1 becomes flexclock1. The root-owned hostname helper also
normalizes its JSON input. Install the updated scripts/web_hostname.py at the
existing /usr/local/libexec/flexclock/web_hostname.py path; permissions and sudoers
are unchanged. Restart only sign-web to deploy the updated Flask code.
Confirmation uses the shared application modal, with Cancel/Escape and Confirm;
the device-name form no longer requires a redundant confirmation checkbox.
Do not change the real hostname as part of automated tests or deployment.


Service activity / Logging
--------------------------
The authenticated /logs page reads only the five allowlisted service journals.
Queries are bounded to 1,000 recent entries in a selected hour/day/week, with
search, severity filters and 50-event pages. Recognized service events are shown
in plain language; unknown diagnostic output is summarized rather than exposed.
The page is read-only and never restarts or changes services. It does not persist
or expose credentials, raw traces or command lines. Search applies to displayed
messages and service names, not raw diagnostic text.
The existing admin account belongs to adm and can already read the system journal.
Fresh installs add SupplementaryGroups=systemd-journal to sign-web only. No new
sudo permission or dependency is required. If history cannot be read, the page
reports that it is unavailable rather than presenting an empty success state.
Restart only sign-web after deploying this revision. Do not restart other services.

Network page layout and connection details
------------------------------------------
Ethernet and Wi-Fi each have one column containing status, current connection
facts and their own settings. Narrow screens stack complete columns. No details,
commands or configuration values are hidden behind expandable controls.
Read-only observations use ip -j address, ip -j -4 route show, resolvconf -l and
iw dev wlan0 link. DNS entries are matched to their source interface, not copied
from another connection. Gateways are extracted as addresses; subnet prefixes
are displayed as dotted subnet masks. Unknown values remain Unavailable.
The static-address form accepts a dotted subnet mask; older CIDR form payloads
remain compatible. Confirmations use the existing application modal. Helper
errors stay in server logs; the page uses short user-facing errors. No additional
packages, permissions, network service changes or sudoers rules are needed.
Deploy with a restart of sign-web only. Do not apply live network settings.
